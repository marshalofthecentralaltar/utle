### Lane MEDIA: seek by amount (item 14)

- Build: `media.forward` and `media.back` carry `seconds` (default 10). Rules parse "keri edasi üks
  minut", "keri tagasi kolmkümmend sekundit", "poolteist minutit", "kaks minutit edasi". The model's
  schema gets the same field. The page side seeks by that amount on `<video>` and `<audio>`; on
  YouTube the player's own seek if the element's `currentTime` is read only.
- Files: `src/core/browserIntent.ts`, `src/core/pageIntent.ts`, `server/intentPrompt.ts`,
  `extension/src/page.ts`, tests beside each.
- Audit criteria and proof:
  1. 12 Estonian phrasings and 4 English map to the right seconds: `npx vitest run src/core/browserIntent.test.ts`, test names listed in the report.
  2. The schema rejects a negative or absent-kind amount: `src/core/pageIntent.test.ts`.
  3. The browser suite's video case seeks 60 s on the fixture video: `npx tsx extension/test/run.ts`, `currentTime` asserted at 60 ± 1.
  4. The eval gains two cases ("keri minut edasi" on the YouTube fake) and passes: `npx tsx scripts/intent-eval.ts` (Ralf's key).
  5. Spec: ARCHITECTURE gets a 29.1 with the grammar; HANDOFF names the lane.

### Lane DOCS: document mode (items 5, 15)

- Build, in order: (a) formatting keys in any editor and in Google Docs: "paksuks", "kaldkirja",
  "allajoonitud", "pealkirjaks", "tavaline tekst", "loendiks", "uus lõik", with the selection
  commands that exist ("vali see lause", "vali lõik", "vali viimased kolm sõna"); (b) **document
  mode**: when the armed box is a document (Docs, a textarea over 500 characters, a rich editor
  with headings), a silence does not close the sentence, one-word ordinary words are never commands,
  the verification that takes words back runs only on a sentence that starts with a command verb,
  and "saada" does nothing. A pause of up to 20 s continues the paragraph; "uus lõik" and "punkt"
  are the only breaks. (c) Reading back: "loe viimane lause ette" through `synth.ts` (shared with READ).
- Files: `src/core/inpage.ts`, `src/core/browserIntent.ts`, `extension/src/page.ts` (the Docs key
  path), `extension/src/engine.ts` (the continuation window), a `fixtures/essay.html`.
- Audit criteria and proof:
  1. Each formatting command sends the right key chord: `src/core/inpage.test.ts`, one test per command.
  2. In document mode "välja", "sulge", "edasi" stay dictation; outside it they stay commands: `extension/src/engine.test.ts`, named tests.
  3. A 15 s pause between two halves of a sentence yields one sentence in the box (fake timers): `engine.test.ts`.
  4. On `fixtures/essay.html` the browser suite dictates two paragraphs, selects the second sentence, makes it italic, and the screenshot `extension/test/out/essay.png` shows it.
  5. On Google Docs (real page, Ralf's session only) the same chords; until then the Docs path is marked unverified in HANDOFF.
  6. The round 3 Google Docs gluing fault (REVIEW-R3 M5) is fixed or its browser test written; the report says which.

### Lane MAIL: mail by voice (items 10, 12, 11)

- Build: (a) Gmail compose by rules and model: "kirjuta meil Marile", "teema: …", "saada" sends,
  "lisa koopia"; the compose dialog's To, Subject and body are reported as one armed group with
  `fieldKind` so "valmis" moves between them. (b) **Addresses on the page**: `readPage` lists
  visible e-mail addresses and phone numbers (text and `mailto:`/`tel:` links) as `contacts`; the
  model may answer `composeTo { address, subject?, body? }`; the engine opens the user's mail
  (Gmail in a new tab, the compose URL with the address prefilled) and arms the body. "Võta see
  meiliaadress siit lehelt ja kirjuta talle, et …" is one careful ask. (c) Spelled addresses from
  round 5 and 6 unchanged; Ralf's wrong read-backs from section 2 step 3 become test cases.
- Files: `extension/src/page.ts`, `src/core/pageIntent.ts`, `server/intentPrompt.ts`,
  `extension/src/engine.ts`, `extension/src/sites.ts`, `fixtures/gmail.html`, `fixtures/cv.html`.
- Audit criteria and proof:
  1. `readPage` on `fixtures/cv.html` returns the two addresses and one phone number, and nothing that only looks like one: `extension/test/run.ts` case, values in the report.
  2. `composeTo` validates and rejects an address not in the page's list: `src/core/pageIntent.test.ts` (the model can never invent a recipient).
  3. The browser suite opens the Gmail stand-in with the address in To, dictates a body, and "saada" clicks Send: screenshot `extension/test/out/mail.png`.
  4. Three eval cases pass on the CV-page fake: `scripts/intent-eval.ts` (Ralf's key).
  5. The request to the server never carries the body of a message the user did not dictate: `server/intent.test.ts` asserts the page summary holds addresses only.

### Lane WAKE: wake word and my places (items 8, 9, 13)

- Build: (a) Listening mode "Äratussõnaga": the recogniser runs always; a final is acted on only
  when it starts with the wake word ("Ütle, keri alla"; the word is a setting, default "Ütle",
  phonetic keys from `phonetic.ts`); dictation into an armed box needs the word once and then
  stays open until 20 s of silence or "aitab". The server strips the word; the bar shows a dot
  while the window is open. (b) **Minu kohad**: a settings list of noun → address (uudised →
  postimees.ee, raadio → the user's station, ilm → ilmateenistus.ee, mail → Gmail, …) with
  Estonian defaults; "vaata uudiseid", "pane raadio mängima", "mis ilm on" open the place; the
  model is given the nouns only. Radio station changes use the existing click intent on the
  station's page.
- Files: `src/core/localIntent.ts`, `src/core/saved.ts` (or a sibling `places.ts`),
  `extension/src/options.ts`, `extension/src/offscreenMain.ts`, `server/intentPrompt.ts`, strings.
- Audit criteria and proof:
  1. With the mode on, 20 finals without the word are dropped and 10 with it are acted on, the word stripped: `src/speech/local.test.ts` and `engine.test.ts`.
  2. "Ütle" inside dictation ("ma tahtsin ütelda") is not a wake: phonetic test in `localIntent.test.ts`.
  3. The settings page shows the list, adds a place by voice, and the browser suite opens "uudised": `extension/test/out/places.png`.
  4. Four eval cases ("vaata uudiseid", "pane raadio käima", "mis ilm on", "ava mu mail") answer the place without the model inventing an address.
  5. Wake mode costs nothing extra on the server: the detector already gates audio; the report shows the capture log with no finals for a minute of room noise in wake mode.

  4. Reading never captures the microphone's own output as speech: the detector test with the synthesised sentence played into the fake microphone yields zero finals while reading, or the report says the bar pauses listening while it reads.
