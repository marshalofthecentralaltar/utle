# Ütle M1 and M2 (core loop) implementation plan

> **For agentic workers:** execute task by task, in order, in this session (native execution).
> Steps use checkbox syntax. Each task is test-first: write the listed tests, watch them fail,
> implement, watch them pass, commit. Exact signatures live in the spec; this plan names the
> tests and the proof for each task. Where the two disagree, fix the spec first.

**Goal:** A local web editor where a spoken or typed sentence becomes a previewed edit that
is accepted, rejected or repaired in one word, with numbered paragraphs and a "which one" question.

**Architecture:** A pure core (document, ops, preview, quick replies, state machine) that returns
effects as data. Thin adapters around it: Chrome speech recognition, a fetch client, React
components, and a dev-server endpoint that asks Claude for exactly one validated tool call.

**Tech stack:** React 19, Vite 8, TypeScript strict, Tailwind 4, Vitest, zod 4,
`@anthropic-ai/sdk`, `tsx` for scripts. Node 22.

**Spec:** `docs/ARCHITECTURE.md`

## Global constraints

- TypeScript `strict: true`. No `any` casts, no `@ts-ignore`, no skipped tests.
- Named exports only. Default exports only where a tool demands one (`vite.config.ts`).
- `src/core/**` imports nothing from the DOM, the network, `speech`, `api`, `ui` or `server`.
- The Anthropic key is read from `process.env.ANTHROPIC_API_KEY` on the server only. No `.env` file is created or committed.
- The server never logs document text or utterances.
- Model id `claude-haiku-4-5`, overridable with `UTLE_MODEL`. At most one retry per utterance.
- Every "done" carries the command and its output. Gate: `npm run check` (typecheck, lint, test, build).
- Stage explicit paths. Local commits only; this repository has no remote.
- Git identity for this repository: marshalofthecentralaltar / 195171080+marshalofthecentralaltar@users.noreply.github.com.

## Review focus

Failure modes the spec implies that are most likely to bite a real user. Each has a test in the named task.

1. The model's `find` text occurs twice or not at all in the block. Expected: nothing changes, one retry, then a plain message. Tests: Task 1 (`find_ambiguous`, `find_not_found`), Task 6 (retry then `not_understood`).
2. A response arrives after the user moved on, or the user speaks during a request. Expected: the late response is ignored; the utterance during a request is ignored with a visible note. Test: Task 5.
3. The recogniser splits one sentence at a pause. Expected: one utterance reaches the editor. Test: Task 8.
4. The recogniser writes "to" or "for" when the user says a number. Expected: counted as 2 and 4 only while a number is expected. Test: Task 3.
5. The API is down or slow. Expected: the mode and the pending proposal are restored, and yes, no and undo keep working. Tests: Task 5 (`interpretFailed`), Task 6 (error mapping).
